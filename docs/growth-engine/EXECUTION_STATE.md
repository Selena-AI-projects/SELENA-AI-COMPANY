  с сохранением отметок обеих сторон (40 записей, строго по возрастанию);
  `content-workflow-repositories.ts` — совпало имя, а не ответственность, поэтому
  профиль Slice 1 остался на своём пути, а проекция Growth уехала в
  `content-workflow-projection.ts`; манифест пакета — объединение без изменения
  значений.
- **Проверено исполнением.** Typecheck `lib`/`worker`/`web` чист; 764 теста
  проходят; все 40 миграций применяются с нуля; реальный путь обновления staging
  (38 → 40) отрепетирован на копии фактического состояния, повтор — no-op.
- **O18 закрыт.** Миграция `0040` даёт политике контента жизненный цикл: одна
  версия в силе, прежние сохраняются, отозванная не восстанавливается. Две

Деплой runner-а по SHA через API невозможен: токен сессии не видит
`parkourcafe/aether-medium`, сборка идёт только через привязку источника под
GitHub-связкой владельца. На релиз `selena-OS` это не влияет.

## Осталось

1. Тестовый Aether как producer: один временный runner в staging-проекте с
   эфемерной базой внутри него. Собственная сеть этой сессии до домена receiver
   не доходит, поэтому запуск обязан идти из разрешённой среды.
2. Тестовый credential моста отдельным каналом, без чтения production-секрета,
   с security-review и отрицательными проверками.
3. Включить `projection` флагом только после готовности тестовых данных.
4. Сквозной прогон: политика и источник через штатный UI → одна fixture-задача →
   две связанные карточки в Inbox.
5. Матрица A01–A14 и браузерная проверка на настоящем staging.
6. Финальный независимый review итогового SHA.

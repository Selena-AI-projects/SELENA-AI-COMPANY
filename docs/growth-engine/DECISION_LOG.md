# Growth Engine — журнал решений

Формат: одна запись — одно решение владельца или одна зафиксированная техническая коррекция ТЗ. Решения архитектуры экосистемы и AI Visibility v1.4 здесь не принимаются.

## 2026-09-06 — Разрешение на локальный срез GE-1…GE-4

**Статус:** DECISION (владелец). Основание: DRAFT-документы в `SELENA-AI-COMPANY`, коммит `507aaa8`.

- Разрешена ограниченная реализация GE-1…GE-4: код, локальные тесты, одноразовые изолированные БД, миграции только в них, локальный запуск Aether/receiver/projection/web, commit и передача через безопасные ветки/PR.
- Не разрешено: GE-5, GE-6, staging/production-изменения, реальные bindings, DNS, auth, боевые secrets, новые облачные базы и сервисы, публикации, live-источники, экспорт из AI Visibility, запуск или изменение scheduled workflows, повторение Master ТЗ. Прикладные LLM/provider calls = 0.
- Это не утверждение дорожной карты и не снятие HOLD.

| ID | Решение | Содержание |
|---|---|---|
| GD-01 | Модель материалов (пункт А) | Одна fixture-задача создаёт два материала: `ARTICLE` и `SOCIAL_ADAPTATION`; у каждого стабильный `aggregate_id = uuid5(NAMESPACE, task_id:kind)`; общий `brief_ref = task_id`; повтор доставки не создаёт карточек; обновление одного материала не заменяет другой; `task.result.ready` остаётся совместимым, ключи не пересекаются. Обещание «один Inbox item на задание» снято |
| GD-02 | Контракт (пункт Б) | `metadata.cta_url` обязателен и валидируется (https, ≤2048, без userinfo и fragment); `version` — версия агрегата-материала, одна и та же в конверте и в `content_versions.version`; только inline `body_markdown` ≤ 48 000 байт UTF-8; отдельный лимит HTTP-тела приёмника 96 KiB; `artifact_ref` вне среза; одинаковые `aggregate_id/version` с другим содержимым → конфликт (`409`), не дубль |
| GD-03 | Bindings (пункт В) | `business_key` — проверочный alias; ключ поиска — `aether_project_id` + `source_environment`; один активный binding на пару во всей базе; projection worker получает только активный binding через SECURITY DEFINER-функцию под ролью `selena_registry_worker_runtime`, затем штатный `set_request_context`; отзыв binding останавливает проекцию; без superuser |
| O1 | База кода | `selena-OS` `05599f98434a8ee66496d5dfe1f523ddde98a4b8`; `Aether-Medium` `29d0e3814e35a8d5dc851db97163013c4cba4bf7`; работа в новых ветках `growth/ge1-4-local-slice` (worktrees); развёрнутые ветки, deployment source и merge старых интеграционных веток не трогаются. Зафиксировано: параллельная ветка `feat/content-os-slice1` (2026-09-06) занимает миграцию `0037`; срез использует `0038`/`0039`, Aether — `0023` |
| O2 | Идентичность | Рабочая принадлежность в Content OS — `organization_id + brand_id`; связь с Aether через точный UUID проекта и доверенный контекст среды; `brand_id` не становится глобальным ID экосистемы; identity AI Visibility не меняется; в GE-1…GE-4 только синтетические организации/бренды/проекты/bindings в одноразовых БД; подтверждение тестовой owner-сессией через штатный серверный механизм |
| O3 | Источник | `SYNTHETIC_FIXTURE`: одна детерминированная задача без LLM создаёт черновик статьи, LinkedIn-адаптацию, brief, claims, source и QA по контракту; в UI и evidence помечено как синтетическое; доказывает передачу, хранение и защитные проверки, не качество исследования или генерации |
| GD-04 | Коррекции по независимому review контракта 1.1 (2026-09-06, коммиты e2fe3d35 / b001012c → исправленные) | Лимит HTTP-тела приёмника 192 KiB вместо 96 KiB (максимальный валидный конверт ≈180 KB); в имя uuid5 материала добавлен `project_id`; длины строк — code points; даты — RFC 3339 с зоной текстом; общие текстовые правила https-адресов; отказ одиночным суррогатам; имена неизвестных полей не эхом. Исторические миграции не менялись |

## Цель программы

Один сквозной проход: **задача в Aether → карточка в кабинете → одобрение
владельца → пост в LinkedIn → метрики обратно.** Источник объёма и границ —
`docs/growth-engine/DECISION_LOG.md` (первая запись, 2026-09-06) и полный
текст ТЗ владельца процитирован в начале `EXECUTION_STATE.md`/переписки этой
программы. Ключевые правила ТЗ, которые нельзя нарушать:

- работать без промежуточных согласований, не спрашивать «продолжать?»;
- на технической развилке — безопасный вариант самому, с записью в
  `DECISION_LOG.md`;
- секреты и строки подключения не должны попадать в чат, логи или GitHub;
  никогда не читать боевой секрет моста; не менять реестр миграций и не
  переписывать историю миграций;
- **одобрение реального контента никогда не делегируется агенту** — только
  владелец;
- запрещено имитировать владельца или фиксировать одобрение от её имени;
- **публикация — только по отдельному слову владельца** «публикуй», даже при
  общем разрешении на автономную работу;
- когда нужен секретный шаг — одна отдельная пошаговая инструкция, не пачкой.

## Архитектура (как есть, 2026-09-09)

```
Aether (агентная студия, отдельный Supabase)
   │  задача → навык selena-growth-draft → 6 файлов контракта
   │  (draft.md, social_linkedin.md, brief.json, claims.json, qa.json, source.json)
   ▼
bridge_outbox → HTTP POST подписанным событием content.draft_ready
   ▼
receiver (Control Room, тот же Postgres, что и кабинет)
   ▼
projection worker → версия материала в Inbox бренда
   ▼
Кабинет (Control Room): Set up (политика) → Sources (источник) →
   Review → Approval (владелец) → Release intent
   ▼
worker: selena-trigger-dispatcher (очередь release_outbox) →
   selena-release-gateway-client → gateway (POST /v1/release-manifests,
   /v1/release-dispatches)
   ▼
gateway: подписывает манифест, авторизует диспетч через БД
   (selena_registry.authorize_provider_dispatch)
   ▼
provider registry (guardPublishing) → Blotato adapter → Blotato API →
   LinkedIn Page
   ▼
метрики: ingestMetrics → Performance в кабинете
```

Три независимых замка публикации (все должны совпасть одновременно, иначе
ничего не публикуется):
1. `environment === "PRODUCTION"` — читается из **одной** переменной
   `SELENA_GROWTH_SOURCE_ENVIRONMENT` (`packages/lib/src/selena-release-providers.ts`);
2. `SELENA_RELEASE_PUBLISH_ENABLED=true` — не поднят нигде, поднимается
   только по слову «публикуй»;
3. живой транспорт вместо `disarmedFetch()` — тоже требует явной сборки.

Привязка канала (`channel_provider_bindings`) — отдельная гарантия: строка
в базе называет, в каком окружении канал разрешён достигать провайдера, и её
может писать только владелец через форму «Bind a channel» (миграции `0032`,
`0045`, `0047`). Форма больше не даёт выбрать окружение произвольно — только
то, которое уже сообщил проверенный `Check connection` (правка от 2026-09-09,
PR #54).

  без явного слова «публикуй».

  что-то, чего она не одобряла.

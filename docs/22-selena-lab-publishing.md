# Публикация материалов Selena Lab

Решение владельца от 29.09.2026 (вариант А). Документ описывает, где живут статьи
Лаборатории, в каком порядке выходят языковые версии и как устроен формат материала.

## Где публикуется

Каждая статья, руководство и эксперимент Лаборатории публикуются в её разделах,
на обоих языках, по одному адресу:

| Язык | Адрес |
|---|---|
| Английский | `/lab/{раздел}/{slug}` |
| Русский | `/ru/lab/{раздел}/{slug}` |

- Раздел — `research`, `guides`, `experiments` или `articles`. Раздел `courses`
  пока без материалов.
- `slug` один для обеих версий и пишется латиницей по-английски. Именно общий
  адрес связывает версии через hreflang и переключатель языка. Отдельный русский
  адрес (транслитом) эту связь разрывает.
- Статьи Лаборатории не публикуются в `/ru/blog`. Роль блога этим решением не
  пересматривалась.

## Порядок выхода

1. Английская версия согласуется владельцем и публикуется первой.
2. После выхода — полная проверка на production (см. «Проверки»).
3. Русская версия готовится по опубликованной английской, а не по более раннему
   черновику, и отдельно согласуется владельцем.
4. Русская версия публикуется в русском разделе под тем же `slug`.

Каждая языковая версия — отдельный согласованный текст. Факты, цифры и описание
продукта в версиях должны совпадать.

Пока опубликована только одна версия, сайт не ссылается на вторую: у страницы нет
hreflang, в sitemap только её адрес, переключатель языка скрыт. Адрес такой
английской статьи нужно добавить в `lib/lab/untranslated.ts` — тест проверяет,
что список совпадает с содержимым. Когда выходит русская версия, адрес из списка
убирают, и связь появляется сама.

## Русский язык

Основное правило: в русской версии как можно меньше английских терминов.

- Переводятся понятия: «исходный замер», «ранний доступ», «доля упоминаний»,
  «ИИ» вместо «AI» в обычном тексте.
- Остаются как есть: имена и названия (Google, ChatGPT, Gemini, Selena Systems,
  названия заведений), имена файлов (`robots.txt`), оригинальные заголовки
  источников.
- Название чужого продукта при первом упоминании можно дать по-русски с оригиналом
  в скобках: «обзоры от ИИ (AI Overviews)».
- Ссылки из русской статьи ведут на русские страницы: `/ru/check`,
  `/ru/visibility`, `/ru/methodology`, `/ru/lab/...`.

## Формат материала

Материалы хранятся в `lib/lab/content.ts`, по одному объекту на язык.

| Поле | Назначение |
|---|---|
| `section`, `slug` | Раздел и адрес, одинаковые в обеих версиях |
| `title` | Заголовок страницы (H1) |
| `metaTitle` | Заголовок для поиска, если отличается от H1. Сайт сам добавляет « — Selena Systems»; итог — 30–60 знаков |
| `summary` | Вступительная строка под заголовком, карточка в списке и описание для поиска: 120–160 знаков |
| `label`, `readingTime` | Метка и время чтения на языке версии |
| `publishedAt`, `updatedAt` | Реальные даты, `ГГГГ-ММ-ДД`; не дата сборки |
| `intro` | Абзацы до первого раздела, без заголовка |
| `blocks` | Нумерованные разделы: `heading`, `paragraphs`, затем `flow` |
| `blocks[].flow` | Текст в том порядке, в каком написан: `paragraph`, `points` (список), `steps` (нумерованный), `subheading` с необязательной меткой доказательности `tag`, `cite` (строка «Источник:» со ссылкой) |
| `blocks[].points` / `steps` / `table` / `code` / `figure` | Прежние поля; выводятся после `flow` в фиксированном порядке |
| `cta` | Блок с кнопкой перед источниками: абзацы, основная кнопка, вторая ссылка |
| `sources` | Первичные источники; ссылки проверяются до публикации |
| `related` | «Смежное»: ссылки на страницы того же языка |
| `socialImage` | Своя карточка для соцсетей; без неё используется общая картинка Лаборатории |

Метки доказательности: `EXTRACTED` / `INTERPRETED` в английской версии,
`ИЗВЛЕЧЕНО` / `ИНТЕРПРЕТИРОВАНО` в русской.

Служебные поля черновика («Подготовлено», «Статус», «Редакционные поля») на
страницу не переносятся.

## Проверки

До PR:

```bash
npm run typecheck
npm test
npm run build
```

После выхода на production — скрипт по всему sitemap:

```bash
SEO_REPORT_DIR=<папка вне репозитория> node scripts/validate-sitemap.mjs
```

Скрипт проверяет ответ сервера, заголовок, описание, canonical, hreflang, язык
страницы, H1, карточку для соцсетей и изображения. Сверх него проверяются:
совпадение текста с репозиторием, разметка Article, ссылки на странице, наличие
статьи в списках раздела и 404 по адресу ещё не вышедшей версии.

Мерж в `main` сразу выкладывает сайт на production (`vercel.json`), поэтому он
делается только с подтверждения владельца.

## Известные ограничения при частых публикациях

- Все материалы лежат в одном файле; при ежедневных публикациях его стоит разбить
  на файл на статью.
- Списки разделов и блок «С чего начать» показывают материалы в порядке массива,
  без сортировки по дате и без ограничения длины.

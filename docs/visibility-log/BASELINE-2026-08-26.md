## Контрольная сверка

- KORA URL-prefix: API и интерфейс показали 11/926 против 17/869.
- Ещё две канонические properties вне публичного журнала также совпали с API.
- Проверка URL-prefix против domain property подтвердила, что более широкая
  область domain property может содержать дополнительные показы; поэтому
  сравниваются только одинаковые canonical properties.
- Selena Systems: служебный аккаунт читает обе URL-prefix properties, данные в
  обоих окнах нулевые. У Google-пользователя, использованного для ручной
  проверки, доступа к этой property нет.

## Граница брендовых данных

Общие клики и показы — точные агрегаты. Google скрывает часть запросов, поэтому
брендовый и небрендовый разрез относится только к видимым query rows и не
должен суммироваться до общего total. После ручной проверки словарь дополнен
подтверждёнными вариантами KORA, Doki и Neva Palace.

Полный технический отчёт охватывает все properties служебного аккаунта, но
публичная таблица ограничена семью проектами из `PROJECTS.md`.

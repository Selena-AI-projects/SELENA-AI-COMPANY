# Редакционный запуск Selena Lab: от повода до черновика

Одна команда читает настроенные источники, отбирает один проверяемый повод про ИИ-поиск и рестораны или отели, подтверждает его дословными местами на странице первоисточника, пишет русскую статью, английскую адаптацию и анонс для Telegram через Claude Code и сохраняет пакет черновика. Ничего не публикует и никуда не отправляет.

```bash
npm run editorial:draft
```

## Что нужно на машине

- Node.js 22.22 или 24 (проверено на 22.22.0 и 24.21.0; флаг `--use-env-proxy` есть с 22.21). Зависимости по lockfile: `npm ci`.
- Claude Code CLI, вход по подписке. Проверка перед запуском:

  ```bash
  claude auth status
  ```

  Ожидается `"loggedIn": true`, `"authMethod": "oauth_token"`, `"apiProvider": "firstParty"`. Переменной `ANTHROPIC_API_KEY` в окружении быть не должно: с ней CLI тарифицируется по API, а не по подписке. Флаг `--bare` не используется.
- Доступ в интернет к источникам из `editorial/sources.json` и к бесплатным каналам интереса (Hacker News, Bluesky, Google News RSS). За корпоративным прокси запускайте с `NODE_OPTIONS=--use-env-proxy`: иначе `fetch` в Node не читает `HTTPS_PROXY`.

## Что делает запуск

1. **Источники.** `editorial/sources.json`: ленты RSS/Atom, каждая с пометкой происхождения (`monitoring-list`, `cited-before`, `new-candidate`). В рабочий набор входят только ленты с заполненным `feedVerified`: их кто-то уже прочитал и разобрал. Остальные — кандидаты; запуск с пустым рабочим набором заканчивается техническим отказом «рабочий набор источников пуст», а не «новостей нет». Проверка лент: `node scripts/editorial/run.mjs --verify-sources --write` читает все ленты, включая выключенные, и записывает в `sources.json`, какие разобрались (`feedVerified`: когда, где, сколько записей, самая свежая) и какие нет (`lastFeedError`). Недоступная лента в обычном запуске попадает в отчёт и не останавливает остальные.
2. **Отбор повода.** Запись проходит, только если в заголовке или аннотации есть и термин про ИИ-поиск, и термин про рестораны/отели, а дата не старше `--lookback-days` (по умолчанию 14). Официальный источник выше отраслевой прессы, свежее выше старого. Оценка печатается в лог.
3. **Подтверждение события.** Страница первоисточника скачивается, превращается в текст и сохраняется в пакет (`page.txt`). Поводом считаются только предложения, которые дословно есть на странице и упоминают обе стороны. Код ответа 200 или совпадение слов в заголовке подтверждением не считаются. Дата берётся из разметки страницы, при её отсутствии — из ленты, с пометкой.
4. **Признаки интереса.** Отдельно от подтверждения: число результатов в Hacker News, Bluesky и число изданий в Google News по запросу из заголовка. Это не доказательство события, а повод упомянуть интерес с числами или промолчать.
5. **Защита от повторов.** `editorial/drafts/ledger.json` хранит каждый взятый повод: ключ первоисточника, слова заголовка, термины, дату. Повод считается тем же, если совпал первоисточник, или заголовок на 50 % и больше состоит из тех же слов в пределах 45 дней, или то же издание в пределах трёх дней называет те же два и более термина. Хеш текста — версия материала, а не защита от повтора темы.
6. **Авторизация и текст.** Перед вызовом модели запуск читает `claude auth status`: нужен вход по подписке (`loggedIn`, `authMethod: oauth_token`, `apiProvider: firstParty`) и отсутствие `ANTHROPIC_API_KEY` в окружении. Иначе — отказ `способ авторизации модели не подтверждён`; на API или другой платный режим запуск не переключается. Затем `claude -p` без инструментов, без сохранения сессии, структурированный ответ по схеме. Бриф — `editorial/PROMPT.md`.
7. **Структурная проверка текста** до сохранения: каждое фактическое утверждение ссылается на существующий id доказательства; английская версия ссылается только на те же id, что русская; в английской нет чисел, которых нет в русской или в доказательствах; в русской нет чисел, которых нет в доказательствах; ссылки только на первоисточник; нет фраз о собственных клиентах, замерах и экспериментах. Ошибка — один повтор с перечнем ошибок в пределах оставшейся оценки бюджета (см. «Расходы»), затем отказ с сохранённым выводом модели. **Смысл утверждений эта проверка не оценивает**: текст может ссылаться на верный id и при этом сказать больше, чем источник (например, «тестируется в США» превратить в «доступно по всему миру»). Поэтому прохождение проверки не называется подтверждением достоверности, в `verification.md` и `manifest.json` два раздельных статуса — структурные проверки и смысловая сверка, и у свежего пакета смысловая сверка всегда «не выполнена». Слова, расширяющие охват («по всему миру», «worldwide» и т. п.), которых нет в доказательствах, попадают в предупреждения как подсказка редактору, не как вердикт.
8. **Пакет.** `editorial/drafts/<дата>-<slug>/`: `article.ru.md`, `article.en.md`, `telegram.ru.md`, `hook.json`, `page.txt`, `writer-output.json`, `verification.md`, `manifest.json`. Заголовок статьи — первая строка файла, заголовок для поиска (13–43 знака) и источники в формате Lab (`hook.json` → `labSources`) готовы для конвертера Control Room. Все отметки времени — Asia/Makassar (UTC+8) и UTC.
9. **Смысловая сверка — вручную, перед одобрением.** Каждое существенное утверждение в `article.ru.md`, `article.en.md` и `telegram.ru.md` — весь текст, не только список фактов — сопоставляется с конкретным фрагментом `page.txt`. Неподтверждённое исправляется, обозначается гипотезой или убирается; результат записывается в раздел «Смысловая сверка» файла `verification.md` (кто, когда, что изменено). До этой записи черновик не считается сверенным.

Коды выхода: `0` — черновик сохранён (структурно проверен, смысловая сверка ещё впереди); `3` — нового повода нет, все подходящие уже в реестре; `2` — отказ (рабочий набор пуст, источники не прочитаны, повод не подтверждён, способ авторизации не подтверждён, текст не прошёл структурную проверку), причина в `editorial/drafts/<дата>-refusal*/refusal.md`; `1` — сбой самого запуска. Каждый запуск дописывает строку в `editorial/drafts/runs.jsonl`.

## Флаги

| Флаг | Что делает |
|---|---|
| `--verify-sources [--write] [--verified-where метка]` | Прочитать все ленты и (с `--write`) записать результат в `sources.json` |
| `--include-unverified` | Читать и непроверенные ленты в обычном запуске; для отладки, не для первого результата |
| `--lookback-days N` | Окно свежести, по умолчанию 14 |
| `--dry-run` | Остановиться после подтверждения повода и напечатать пакет доказательств; модель не вызывается |
| `--allow-repeat` | Переписать уже взятый повод; новая версия добавляется в `manifest.json` и реестр |
| `--only-source id` | Читать одну ленту |
| `--candidate-url url` | Пропустить ленты и проверить одну страницу |
| `--budget-usd N` | Значение для `claude -p --max-budget-usd` первой попытки, по умолчанию 1; повтор получает только остаток по оценке CLI. Это ограничение CLI по его собственной оценке, не гарантированный денежный потолок |
| `--model name` | Модель для `claude -p`; без флага — модель по умолчанию CLI |
| `--no-interest` | Не собирать признаки интереса |
| `--fixtures map.json`, `--writer fixture` | Только для тестов: локальные файлы вместо сети и заглушка вместо модели. Такой пакет помечен как тестовые данные |

## Первый запуск

Сетевая политика контейнера сессии 11.10.2026 отказывала в соединении со всеми хостами лент (`editorial/NETWORK_2026-10-11.md`), поэтому ни одна лента ещё не читалась и рабочий набор пуст. Порядок после открытия доступа, в контейнере или на вашей машине:

```bash
npm ci
node scripts/editorial/run.mjs --verify-sources --write --verified-where <где запускали>
npm run editorial:draft
```

Проверка лент покажет по каждой `ok`, `unreachable` или `unreadable`. Для `unreachable`/`unreadable` у источника с `feedGuess: true` адрес ленты — предположение: откройте сайт издания, найдите настоящий адрес RSS (обычно `/feed`, `/rss`, `/rss.xml` или ссылка `application/rss+xml` в коде страницы) и поправьте `feed`. Источник можно выключить строкой `"enabled": false`; исторический список при этом не удаляется.

Если ленты прочитаны, а запуск закончился отказом «нет подходящего повода», это нормальный результат: статья пишется только по поводу, который прошёл проверку. Если ленты не прочитаны, это технический отказ, и он так и записывается.

## Расходы

Запуск использует только `claude -p` под вашим входом в Claude Code и перед каждым модельным вызовом проверяет, что вход подписочный (см. шаг 6). Разрешён только включённый лимит подписки; API-оплата, usage credits и любые дополнительные расходы не разрешены, и запуск на них не переключается — при другом способе авторизации он отказывает, не пишет.

Что запуск знает о расходе: поле `total_cost_usd` из ответа CLI — **оценка самого CLI**, не фактическое списание (в прогонах 11.10.2026 — $0,20 и $0,24 за статью по этой оценке). Относится ли вызов к лимиту подписки или к платному usage, видно только в вашем аккаунте Anthropic; из запуска и из сессии это недоступно, и отсутствие API-ключа само по себе этого не доказывает. `--budget-usd` (по умолчанию 1) передаётся как `--max-budget-usd` первой попытке; если текст не прошёл структурную проверку, повтор получает только остаток (`budgetUsd − оценка первой попытки`), а при исчерпанном или неизвестном остатке не выполняется. Оценки всех попыток суммируются и сохраняются в `manifest.json` → `writer` (`attempts`, `estimatedCostUsd`, `remainingBudgetUsd`). Это ограничение по оценке CLI, не гарантированный денежный потолок. Платных источников и сервисов запуск не вызывает.

## Что действует для этого запуска

Утверждённое задание 11.10.2026: русская статья, английская адаптация, русский анонс для Telegram, сохранение черновика без публикации. Более старые документы о каналах (LinkedIn как основной канал Control Room, английский кластер «не раньше Q1 2027», каналы личного бренда) не переписываются; для этого запуска приоритет у утверждённого задания, стратегия каналов им не меняется.

## Что в git, что нет

Скрипты (`scripts/editorial/`), бриф, список источников, этот файл и тесты (`tests/unit/editorialRun.test.ts`) — в репозитории. Папка `editorial/drafts/` вместе с реестром и журналом запусков — исключена из git: черновики, пока их не одобрил владелец, в репозиторий не попадают.

## Чего запуск не делает

- Не публикует и не заменяет существующий путь: одобренная статья попадает в Lab через Aether и Control Room (репозитории `Aether-Medium` и `selena-OS`), которые открывают PR с парой файлов `data/lab/<раздел>/<slug>.<ru|en>.json` по правилам `docs/22-selena-lab-publishing.md`. Папка `editorial/drafts/` — временное место для первого результата; пакет из неё передаётся в Aether, а не мимо него.
- Не ходит в платные сервисы (Oxylabs, Ahrefs, DataForSEO) и не использует API-ключ.
- Не меняет расписания и настройки сервисов.
